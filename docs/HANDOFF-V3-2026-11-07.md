## Como publicar (/v3 dentro da produção)

Prévia ("Preview") da Vercel nesse projeto **pede login** (proteção do time 4-yu-mkt):
não serve para mandar ao cliente. Por isso as versões entram como pastas da produção.
A CLI `vercel` local está logada como `4yumkt-8631` (time 4-yu-mkt). O conector Vercel
do Claude é outra conta (time "freela1") e não pode criar projeto.

```bash
# na v3
PREVIA_ESTATICA=1 npx astro build && cp -r .vercel/output/static /home/gabfelix/dev/bm-v3-static
git fetch origin
git worktree add --detach /home/gabfelix/dev/bm-deploy-main origin/main
git worktree add --detach /home/gabfelix/dev/bm-deploy-v2 origin/v2
(cd /home/gabfelix/dev/bm-deploy-main && npm ci && npx astro build)          # node_modules de verdade
(cd /home/gabfelix/dev/bm-deploy-v2 && npm ci && PREVIA_ESTATICA=1 npx astro build)
D=/home/gabfelix/dev/bm-deploy-main/.vercel/output/static
(cd /home/gabfelix/dev/bm-deploy-v2 && node tools/montar-v2.mjs .vercel/output/static $D)
node tools/montar-versao.mjs v3 /home/gabfelix/dev/bm-v3-static $D
mkdir -p /home/gabfelix/dev/bm-deploy-main/.vercel && cp .vercel/project.json /home/gabfelix/dev/bm-deploy-main/.vercel/
(cd /home/gabfelix/dev/bm-deploy-main && vercel deploy --prebuilt --prod --scope 4-yu-mkt --yes)
# conferir /, /v2/, /v3/ e depois remover as worktrees e a pasta bm-v3-static
```

- `PREVIA_ESTATICA=1` faz o contato (pt e en) sair pré-gerado, por um hook em
  `astro.config.mjs`. **Não** usar `export const prerender = <expressão>` nas páginas:
  o Astro não avalia e cai no padrão estático (isso quebrou o `?assunto=` uma vez).
  Na prévia estática o assunto do link é marcado no navegador (script em `views/Contato`).
- Só publicar em produção com pedido do Gabriel. A raiz (v1) não deve mudar sem ordem.

## Armadilhas do ambiente

- **O dev server serve CSS velho** depois de reescrever arquivos grandes. Sintoma: página
  "sem estilo" ou com o estilo antigo. Reiniciar: matar o processo e subir de novo.

| Nome | Onde | Para quê |

### Passo a passo para ligar

1. **Criar o projeto** no Supabase (região São Paulo). Guardar a senha do banco.
2. **Migrações:** em Connect → Session pooler, copiar a connection string e rodar
   `SUPABASE_DB_URL='postgresql://postgres.<ref>:<senha>@...:5432/postgres' npm run cms:migra`.
   Aplica 001–005 e registra em `cms_controle.migracoes`; pode rodar de novo.
3. **Auth** (Authentication → Sign In / Providers e URL Configuration): desligar
   "Allow new users to sign up" (contas só pelo `cms:editor`); Site URL = domínio do site;
   em Redirect URLs, `https://<domínio>/painel/nova-senha/` (e
   `http://localhost:4391/painel/nova-senha/` para testar). Traduzir o e-mail de
   "Reset password" em Email Templates.
4. **Contas de editor:** pôr `PUBLIC_SUPABASE_URL` e `SUPABASE_SERVICE_ROLE_KEY` no `.env`
   e rodar `npm run cms:editor -- <email do Jus> "Juscelino Bertoncini"` e
   `npm run cms:editor -- <email da Bia> "Beatriz Mendonça"`. Cada um imprime a senha
   uma vez; entregar por canal seguro. Eles podem trocar em "Esqueci minha senha".
5. **Carga inicial:** `npm run cms:importa -- --seco` (confere) e `npm run cms:importa`.
   Leva os 7 textos de `src/content/artigos/`, idempotente (texto que já está no banco não
   é tocado; `--sobrescreve` regrava). As capas continuam como `/media/capas/...` do site.
   A categoria é gravada na grafia da área ("Direito Digital"), igual à lista do painel.
6. **Vercel:** em Settings → Environment Variables, `PUBLIC_SUPABASE_URL`,
   `PUBLIC_SUPABASE_ANON_KEY` e `VERCEL_DEPLOY_HOOK`. **Criar antes do deploy**, senão o
   build sai sem banco.
7. **Gancho de deploy:** Settings → Git → Deploy Hooks, criar um para a branch que estiver
   na raiz do domínio e pôr a URL em `VERCEL_DEPLOY_HOOK`.
8. Conferir no banco real o que nunca foi testado com Supabase de verdade: editor lê
   rascunho e anônimo não; upload de capa (o `sharp` vai na função; se falhar, a imagem
   sobe sem redução, com as medidas do navegador); troca de senha pelo e-mail.

O fluxo inteiro (login, lista, novo, editar, capa, lote, apagar, troca de senha, sem
JavaScript, importação idempotente e o loader lendo as colunas novas) foi testado em
07/11 contra um Supabase falso local; o real ainda não.

### O painel na prévia /v3

Na prévia `/v3/` (build com `PREVIA_ESTATICA=1`, só a pasta estática vai para dentro da
produção) **o painel não funciona**: ele precisa de servidor (rotas `prerender = false`
e `/api/painel/*`), e a função de servidor da v3 não vai junto. Só funciona quando a v3
virar a raiz do domínio ou ganhar um deploy próprio. Limite da Vercel a lembrar: corpo de
requisição até 4,5 MB; o painel reduz a imagem no navegador e recusa acima de 4 MB.
