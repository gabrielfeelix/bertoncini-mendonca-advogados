## Preparar outro computador

1. `git clone git@github.com:gabrielfeelix/bertoncini-mendonca-advogados.git` e
   `git checkout v3`.
2. `npm ci`
3. Copiar o `.env` (o Gabriel já guardou). Ele tem: tokens da Vercel, da Hostinger e
   do Supabase (Management API), as chaves do Supabase, a conexão do banco, as
   variáveis da Brevo e a chave SMTP. **Nunca commitar.**
4. Ligar o vínculo com o projeto da Vercel (a pasta `.vercel` não vai para o Git):
   `vercel link --yes --project bertoncini-mendonca-advogados --scope website-207d --token "$VERCEL_TOKEN"`
5. Servidor local: `npx astro dev --port 4391 --host` → http://localhost:4391/
   (com o `.env`, o local lê os artigos do Supabase de verdade).

## Como publicar (deploy)

Desde a noite de 19/11/2026 o código também fica no GitHub do escritório:
`github.com/bertoncinimendonca/site` (privado, branch padrão `v3`; conta
`bertoncinimendonca`, login com `contato@bertoncinimendonca.adv.br`). O workflow
`.github/workflows/publicar.yml` monta e publica o site na Vercel (time website-207d)
e roda em três casos:

- **publicar, despublicar ou apagar texto no painel** (o servidor dispara o evento
  `publicar` com `GITHUB_TOKEN_PUBLICAR`, que está na Vercel e no `.env`);
- **push na branch `v3` do repositório do escritório**;
- manualmente, em Actions → Publicar o site → Run workflow.

Leva cerca de 1min30. Segredos do repositório: `VERCEL_TOKEN`, `PUBLIC_SUPABASE_URL`,
`PUBLIC_SUPABASE_ANON_KEY`.

Para publicar uma mudança de código, envie para os dois repositórios:

```bash
git push origin v3                       # gabrielfeelix/bertoncini-mendonca-advogados
G=$(grep -E "^GITHUB_TOKEN_PUBLICAR=" .env | cut -d= -f2-)
git push "https://x-access-token:$G@github.com/bertoncinimendonca/site.git" v3:v3   # publica
```

Publicar direto pelo terminal continua funcionando (útil para testar):
`npx astro build && vercel deploy --prebuilt --prod --yes --scope website-207d --token "$VERCEL_TOKEN"`.
