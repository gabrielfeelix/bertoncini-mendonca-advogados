## Preparar outro computador

1. `git clone git@github.com:gabrielfeelix/bertoncini-mendonca-advogados.git` e
   `git checkout v3`.
2. `npm ci`
3. Copiar o `.env` (o Gabriel já guardou). Ele tem: tokens da Vercel, da Hostinger e
   do Supabase (Management API), as chaves do Supabase, a conexão do banco, as
   variáveis da Brevo e a chave SMTP. **Nunca commitar.**
4. Ligar o vínculo com o projeto da Vercel (a pasta `.vercel` não vai para o Git):
   `vercel link --yes --project bertoncini-mendonca-advogados --scope website-207d --token "$VERCEL_TOKEN"`
5. Servidor local: `npx astro dev --port 4391 --host` → http://localhost:4391/
   (com o `.env`, o local lê os artigos do Supabase de verdade).

## Como publicar (deploy)

O projeto da Vercel **não está ligado ao GitHub**: push não publica. Publicar é pelo
terminal, com o token do `.env`:

```bash
T=$(grep -E "^VERCEL_TOKEN=" .env | cut -d= -f2-)
npx astro check            # 0 erros
npx astro build            # gera .vercel/output (lê os artigos do Supabase)
vercel deploy --prebuilt --prod --yes --scope website-207d --token "$T"
```

Conferir depois: `/`, `/escritorio/`, `/contato/`, `/painel/entrar/`. As variáveis do
servidor (Brevo, Supabase, inclusive a chave secreta, só no servidor) já estão na Vercel.
